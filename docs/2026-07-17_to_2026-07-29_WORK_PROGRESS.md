## 二、按时间推进的工作

### 7月17日—25日：无可追溯代码提交

- 本仓库在此期间没有可追溯的 Git 提交记录。

### 7月26日：研究路线冻结与科学证据链搭建

- 完成 GeoReliab 选题梳理、文献调研、候选方案比较与创新性评估。
- 确立双 MVE 决策机制：Geometry causal audit 为条件式主线，GeoReliab 为第一备选；冻结模型、数据划分、统计检验、资源预算和主线选择阈值。
- 实现 artifact contract、readiness 检查、统计模块、决策 gate、CLI 和回归测试。
- 建立 DTU/TartanAir 的真实数据准备与 provenance 流程，包括原始字节哈希、固定场景/视角清单、渲染与退化过程溯源。
- 完成 DTU 原生几何审计、场景级统计、下游过滤及 zero-update 证据构建。
- 收紧科学证据路径：科学 PASS 必须从冻结的阶段证据重算，禁止通过手写聚合结果、缺失 provenance 或无效预测绕过验证。

### 7月27日：真实 MVE 运行器与 A100 部署控制

- 完成 VGGT 与 MASt3R 的适配器边界；无效预测被保留用于审计，但不能被 gate 视为有效科学证据。
- 完成可恢复的真实 MVE runner：固定任务表、哈希分片、原子写入、断点恢复、账本、锁恢复、日志留存和预算检查。
- 冻结核心实验规模：P3 为 **2 模型 × 20 场景 × 10 条件 = 400 条**主测试记录；P5 为 **480 条** zero-update 子集记录。
- 完成 A100 部署配置、环境/权重/源码哈希校验、P0—P6 阶段化脚本和操作手册。
- 完成独立审查的整改与复核。完整本地测试达到 **198 passed**；A100 部署相关测试 **17 passed**，脚本静态检查与 Python 编译检查均通过。
- 远程 readiness 证据表明：已确认两张空闲 A100 80GB GPU、约 1.7TB 可用空间，冻结的模型环境、源码提交及权重哈希可匹配；DTU Rectified 和 TartanAir 仍需执行 P0 数据物化。

### 7月28日：运行鲁棒性与证据语义加固

- 修复远程 Range 下载、TartanAir ZIP 索引、网络中断重试、P0 readiness、雾化质量检查与物化清单恢复等问题。
- 加强跨运行环境 artifact 序列化一致性，保证冻结数据语义不因运行环境差异而变化。
- 将冻结的 MASt3R 输出纳入证据路径，同时保持 P1 预检的严格性。
- 保证未完成证据维持非终态、阶段锁定；继续贯彻“失败可审计、结果不可伪造、固定计划不可静默缩减”的 fail-closed 原则。

### 7月29日：存储架构重构与科学协议保护

- 启动存储专项重构，新增 storage audit、内容寻址、无损压缩与缓存保留策略。
- 对科学协议加锁，冻结数据划分、退化参数、模型/条件组合、50 GPU·h 预算及 1TB 存储上限，确保存储优化不改变科学实验语义。
- 制定资源控制目标：总存储硬限制 1TB，预估占用控制在 900GB 以下，保留数据目标低于 500GB。
- 规定存储重构不触发新的模型推理；再次启动 P1 前需针对精确部署提交重新选择 GPU。
